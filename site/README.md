# Birehan Zewdie: Portfolio Site

Static, dual-mode (dark / light) Next.js 15 portfolio that reads content directly from the `info.md` files and `images/` folders that live alongside this `site/` directory in the parent repo.

Adding a new project = drop a folder in `../client_projects/` (or `../projects/`) with an `info.md` (frontmatter optional) and an `images/` subfolder. The site picks it up on the next build.

---

## Stack

- **Next.js 15** (App Router) · **React 19** · **TypeScript 5**
- **Tailwind CSS v4** + **shadcn-style** primitives (Button, Card, Badge)
- **next-themes** for persistent dark / light mode
- **react-markdown + remark-gfm + rehype** for rendering `info.md` case studies
- **gray-matter** for YAML frontmatter
- **lucide-react** for icons
- Static export (`output: "export"`) → deployable as a folder of HTML to any static host.

## Local development

```bash
# from site/
npm install
npm run dev          # http://localhost:3000
```

`npm run dev` runs `predev` which copies `../client_projects/**/images`, `../projects/**/images`, `../certificates/**` and `../resumes/resume.pdf` into `public/content/` and `public/resume.pdf` so Next can serve them.

Type check the project:

```bash
npm run typecheck
```

## Build

```bash
npm run build        # writes the static site to ./out
```

Open `out/index.html` directly in a browser, or serve it locally:

```bash
npx serve out
# or
cd out && python3 -m http.server 4000
```

## Deploy

The `out/` folder is the entire site. Three options below.

### Cloudflare Pages (recommended)

```bash
# 1. Sign in once (uses wrangler under the hood)
npx wrangler pages project create birehan-portfolio --production-branch=main

# 2. Build locally
npm run build

# 3. Push to Cloudflare
npx wrangler pages deploy out --project-name birehan-portfolio
```

For continuous deploy from GitHub, in the Cloudflare dashboard:
- **Build command:** `npm run build`
- **Output directory:** `out`
- **Root directory:** `site`
- **Framework preset:** Next.js (Static HTML Export)

### GitHub Pages

1. In the repo `Settings → Pages`, set **Source** to “GitHub Actions”.
2. Add `.github/workflows/pages.yml` (build `npm run build` in `site/`, then `actions/upload-pages-artifact` on `site/out`, then `actions/deploy-pages`).
3. Push to `main`.

### Vercel (free tier)

```bash
cd site
npx vercel --prod
```

(Vercel auto-detects Next.js; static export works as-is.)

## How content is sourced

The site reads from sibling folders in this repo:

```
portfolio/
├── client_projects/<slug>/
│   ├── info.md          ← frontmatter + body (full case study)
│   └── images/*.png     ← cover (main_image.png) + gallery
├── projects/<slug>/     ← personal / open-source projects
│   ├── info.md
│   └── images/*.png
├── certificates/
│   ├── 10_academy/      ← single award with images/
│   ├── competitive_programming/<award>.png
│   ├── coursera/<course-name>/{info.md, image.png}
│   └── udemy/<bootcamp>.png
└── resumes/             ← PDFs (`resume.pdf` is copied to `/resume.pdf` when present)
```

### Adding a new client project

1. Create `../client_projects/my-new-project/info.md` with frontmatter:
    ```yaml
    ---
    title: "Project name"
    role: "Your role on it"
    summary: "One-paragraph hook."
    outcome: "What measurably changed."
    stack: [FastAPI, Next.js, …]
    links:
      live: https://example.com
      github: https://github.com/...
    featured: true   # show on homepage
    order: 1         # lower = higher in featured list
    ---
    ```
2. Drop screenshots in `../client_projects/my-new-project/images/`. Name the cover `main_image.png` (or anything matching `^main`).
3. Run `npm run dev` (or rebuild). Done.

## Notes

- Candid sections (`## Brutally honest…`, `## Honest limits…`, `## What I'd highlight in an interview`) inside `info.md` are **automatically stripped** from the public case study. They stay in the source file for your own reference.
- One project folder name has a typo (`legal_contract_adivisor`). The slug is normalized to `legal-contract-advisor` in URLs without renaming the folder.
- Coursera folders with spaces (e.g. `Machine Learning with Python`) are URL-encoded by the content layer.
- The `out/`, `node_modules/`, `public/content/`, and `public/resume.pdf` folders are git-ignored; they are regenerated by `npm run build`.
